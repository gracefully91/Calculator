# 손그림 좌표 → LLM 함수 제안 작업 기록

## 설계 결정

기존 보라색 자유필기는 화면 위의 주석이다. 그래프를 확대하거나 이동해도 같이 움직이지 않는 것이 의도이므로, 이를 함수 추정 데이터로 쓰면 좌표 의미가 사라진다.

따라서 주석과 별도로 주황색 **함수 스케치** 레이어를 만들었다. 이 레이어는 포인터 위치를 현재 그래프의 실제 world 좌표 `(x, y)`로 변환해 저장한다. JSXGraph 보드가 이동·확대된 경우에도 보드 bounding box를 읽어 같은 좌표계로 유지한다.

## LLM 흐름

1. 사용자가 `함수 스케치` 모드에서 하나 이상의 곡선을 그린다.
2. 앱은 각 스트로크를 최대 36개 좌표 점으로 압축하고, mathjs ASCII 식과 엄격한 JSON 출력 형식을 요구하는 프롬프트를 만든다.
3. 사용자는 선호하는 LLM에 프롬프트를 복사·붙여넣고 JSON 답을 다시 앱에 붙여넣는다.
4. 앱이 JSON·수식·도메인을 먼저 검증한다. 통과한 식만 미리보기와 `이 식 적용` 버튼을 보인다.
5. 적용은 명시적 버튼을 눌러야 하며, 유효하지 않은 응답은 기존 함수를 절대 덮어쓰지 않는다.

여러 스케치는 LLM에 별도 선으로 전달되며, LLM은 별도 함수라면 `independent: true`를 반환하도록 안내받는다.

## 왜 직접 API 호출이 아닌가

초기 버전은 API 키·서버·비용·모델 종속성을 만들지 않는 복붙 방식이다. 이후 직접 LLM 연결을 추가하더라도 입력 좌표·출력 JSON·검증·미리보기 계층은 그대로 재사용할 수 있다.

## 검증

- 좌표 샘플 프롬프트 생성, fenced JSON 파싱, 잘못된 LLM 식 거부를 단위 테스트했다.
- 화면 스트로크가 world 좌표로 변환되는지 테스트했다.
- 유효한 LLM 응답만 적용 UI가 열리는지 테스트했다.
- 전체: 26개 테스트 파일, 157개 테스트 통과.
- `npx oxlint`: 실패 없음. 기존 `LinkedFunctionPanel.jsx` effect 경고 2개만 유지.
- `npx vite build`: 성공.
