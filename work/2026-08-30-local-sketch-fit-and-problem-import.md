# 로컬 손그림 보정과 브라우저 LLM 문제 분석 작업 기록

## 두 흐름을 분리한 이유

손그림을 식으로 바꾸는 일과, 문제 이미지를 읽어 그래프 구성을 만드는 일은 서로 다른 입력과 실패 방식이 있다. 따라서 하나의 LLM 기능으로 섞지 않았다.

| 흐름 | 기본 동작 | LLM 역할 |
| --- | --- | --- |
| 손그림 함수 보정 | 앱이 좌표 점에 1~3차 다항 회귀를 해 가장 단순한 후보를 제안 | 복잡한 곡선·조각함수일 때 선택적으로 더 좋은 후보를 제안 |
| 문제 분석 가져오기 | 앱은 검증·미리보기·상태 적용을 담당 | 브라우저 LLM이 문제 이미지와 프롬프트를 해석해 JSON을 생성 |

## 손그림 기본 보정

- 주황색 함수 스케치의 world 좌표에 대해 직선·이차·삼차 최소제곱 후보를 계산한다.
- 오차와 복잡도 패널티를 함께 비교해 지나치게 높은 차수의 식을 피한다.
- 적용 전 식과 오차를 보여 주며, 명시적으로 `자동 보정 식 적용`을 눌러야 기존 함수가 바뀐다.
- 복잡한 개형은 기존의 수동 LLM 보조를 사용한다. 이 경로도 이미지가 아니라 좌표 샘플을 LLM에 전달한다.

## 브라우저 LLM 문제 분석

- `LLM 문제 분석 가져오기`에서 고정 프롬프트를 복사한다.
- 사용자는 문제 이미지와 프롬프트를 자신이 사용 가능한 브라우저 LLM에 넣는다.
- LLM이 반환한 JSON을 붙여넣으면 앱이 왼쪽 조각함수, 오른쪽 모드/수식, 파라미터, `t`를 검증한다.
- 유효한 결과만 미리보기·`그래프에 적용`을 제공한다. 잘못된 응답은 현재 그래프를 덮어쓰지 않는다.
- API 키, 서버, 특정 LLM 계정 연결은 필요 없다. 직접 API 연결을 나중에 추가해도 동일 JSON 계약을 재사용한다.

## 검증

- 다항 회귀 후보와 다중 독립 곡선, LLM 함수 JSON, 문제 분석 JSON을 단위 테스트했다.
- 유효한 문제 분석이 실제 App의 왼쪽/오른쪽 상태·파라미터·`t`까지 적용되는지 테스트했다.
